# v0.3.3

> Released: 2026-10-19

## Highlights

- **Letta provider connections** — Companies can now configure and manage Letta Cloud provider connections (API endpoints, auth modes, secret references) through the provider connections API. Supports default connections per company and metadata storage. ([#PR])
- **Team import for Letta agents** — The Donjon Core starter team (DonDog, Alfie, Chef) now ships with complete `.af` agent files, enabling one-command team import via `doerai company import`. Includes orchestration agent configurations with memfs bindings pre-wired. ([#PR])
- **Letta model & agent discovery** — New API surface to discover available Letta models and agents from configured provider connections, supporting the adapter configuration workflow. ([#PR])

## Improvements

- **Permission guards refactored** — `requirePermission`, `requireRole`, and related guards moved to dedicated `middleware/permission-guard.ts` with their own test coverage. The `middleware/index.ts` barrel no longer re-exports them (avoids dragging `services/access` into route test setups, eliminating timeout flakes).
- **Migration journal rebuilt** — Renumbered provider connections migration from `0053` → `0057` to avoid collision with main branch's `0053_goal_success_criteria`, `0054_cost_events_cost_estimated`, `0055_time_tracking`, `0056_email_notifications`.
- **Vitest project added** — `packages/shared` now participates in the test matrix, improving shared-type coverage.

## Fixes

- **CLI workspace command test** — Fixed use of commander's private `_args` property, replaced with public `registeredArguments` API.
- **Orphaned TimeTracker test removed** — Feature branch's `TimeTracker.test.tsx` tested components (`TimerButton`, `TimeEntryList`, `TimeSummaryCard`) not present in main's TimeTracker; removed to unblock build.
- **Duplicate route registration** — Fixed double-import of `timeTrackingRoutes` and `accessService` in `server/src/app.ts` and `permission-guard.ts` introduced by auto-merge.

## Database Migrations

Two new migrations run automatically on startup:

- **Migration 0057** (`provider_connections`) — Creates the `provider_connections` table with FK to `companies` and `company_secrets`, unique index on `(company_id, name)`, and supporting indexes.
- Migration `0053`–`0056` (goal success criteria, cost events, time tracking, email notifications) were already present on `main` and are unchanged.

Both are additive — no existing data is modified.

## Upgrade Guide

Standard `doerai` startup will apply new migrations automatically. No manual intervention required.

If you have a worktree instance, run `doerai worktree:refresh` to pull the latest schema.
