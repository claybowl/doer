# v2026.729.0

> Released: 2026-07-29

## Highlights

- **Unified Letta adapter** — letta-code now uses `@letta-ai/letta-agent-sdk` for a unified local-first experience, supporting multiple LLM providers and backends (local, cloud_attached)
- **Goal success criteria** — goals now support `successCriteria` field for tracking objective completion conditions across the fleet
- **Goal and project tool intercepts** — agents can now read, create, and update goals and projects directly through the adapter tool system, plus goal/parent linkage on paperclip issues
- **Plugin system overhaul** — add repair, purge, and link page management for installed plugins
- **Constellation auto-detection** — agent IDs starting with `agent-` (not `agent-local-`) automatically infer `cloud_attached` backend — no manual toggle needed

## Improvements

- **Heartbeat resilience** — adapter execution retries on `.git/config.lock` races from concurrent letta-code agents; run activity refreshed during streaming to prevent orphan reaper kills
- **Goal success criteria** — schema, validators, shared types, and plugin goal service all support the new `successCriteria` field
- **CLI status command** — `doerai status` gives quick dashboard overview of agents, costs, approvals, and budget
- **Release updater checks** — health diagnostics and auto-update readiness reported in the desktop app
- **Letta model dropdown** — UI allows selecting custom model handles for Letta agents
- **Simplified onboarding** — streamlined spin-up flow for new instances
- **LLM provider mapping** — Groq and other provider API keys correctly mapped for local letta-code backend
- **Desktop release validation** — automated artifact checks before desktop release

## Fixes

- **Duplicate CLI `status` command** — resolved Commander.js conflict between `registerStatusCommands()` and inline command definition
- **Missing `successCriteria` in type contracts** — added to plugin goal create params and UI test fixtures
- **Stale Letta mounts** — memfs fs-mount strategy now repairs stale mounts automatically
- **Letta CLI adapter** — always uses `--new` flag and adds headless tool constraint for stable execution
- **Cloud stream buffering** — fixed messageId-based fragmentation in letta-cloud streaming responses
- **Plugin runtime bundles** — ensure distributed plugin builds include all required files
- **Live transcript streaming** — smoothed agent output rendering in the UI

## Upgrade Guide

No breaking changes. The `successCriteria` field on goals is additive — existing goals will have `null` until populated via the API or agent tool calls.
