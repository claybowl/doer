# v2026.619.0

> Released: 2026-06-19

## Highlights

- **Letta Cloud — ngrok elimination** — The `letta-cloud` adapter no longer relies on E2B→ngrok tunnels for Paperclip issue operations. All five issue tools (`create_paperclip_issue`, `read_paperclip_issues`, `read_paperclip_issue`, `update_paperclip_issue`, `post_issue_comment`) are now intercepted adapter-side and executed as direct HTTP calls from the Node.js server. Python stubs registered in the Letta tool registry return a no-op placeholder so E2B never attempts a localhost connection.

- **Heartbeat context injection** — The heartbeat service now pre-fetches the issue title and description and injects them into the agent execution context before wake. The `letta-cloud` adapter inlines this into the TASK MODE wake message, giving agents full issue context without an extra `read_paperclip_issue` round-trip.

- **Self-healing tool attachment** — `ensurePaperclipIssueToolsAttached()` runs non-blocking on every agent wake. It registers the five Paperclip stubs in the Letta tool registry if missing and attaches them to the agent — once per agent per server lifetime.

## Improvements

- **CI build ordering** — `release.yml` and `verify_stable` now pre-build all internal workspace packages (excluding `@doerai/server` and `@doerai/ui`) before running `pnpm -r typecheck`. This resolves a NodeNext module-resolution failure where `@doerai/db` could not find `@doerai/shared` on a fresh CI runner.

- **Wake message quality** — TASK MODE wake messages now include an `── ISSUE BODY ──` block when the description is available from context injection, with an explicit fallback instruction when it is not.

## Fixes

- **MakerSquirrel platform guard** — Desktop build no longer crashes on non-Windows platforms; `MakerSquirrel` instantiation is guarded behind `process.platform === 'win32'`.

## Desktop

- Desktop version bumped to **0.1.1**. Binaries available for Mac (arm64), Windows (x64), and Linux (x64 AppImage).
